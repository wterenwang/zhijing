# 数据闭环

## PM视角要点

- 具身智能产品的竞争力越来越取决于数据飞轮，而非单次模型发布。
- 数据闭环 = 采集 → 标注/质检 → 训练 → 部署 → 在线评测 → 发现 bad case → 再采集。PM 应 owner 整个 loop 的节奏与优先级。
- 每个环节都有产品决策：采什么场景、标注粒度、A/B 评测指标、多少 bad case 才触发再训练。
- 没有闭环的团队会陷入「demo 永远在同一个桌子拍」的陷阱，无法规模化。

## 核心概念

### 闭环六步

```
1. 场景定义 → 2. 数据采集 → 3. 数据治理 → 4. 模型训练 → 5. 仿真/真机评测 → 6. 线上监控与回流
```

### 数据采集

- **来源**：遥操作、自主探索、人类在环、仿真合成
- **元数据**：场景 ID、物体类别、光照、失败原因标签
- **PM 输出**：数据采集 playbook、场景覆盖矩阵

### 评测体系

- **离线**：held-out 验证集成功率、轨迹误差
- **在线**：任务完成率、平均耗时、人工介入次数、安全事件数
- **对比**：版本间 regression 检测，新模型不得在某些核心场景退步

### 与 Week 2 总结

Day 8-13 学的分层架构、硬件、VLA/RL/IL，最终都要汇入数据闭环。产品经理的第2周收官，是画出自己目标产品的第一版闭环 diagram。
