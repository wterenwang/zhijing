# VLA 深度案例：「把杯子拿来」

## PM视角要点

- 「Bring me the cup / 把杯子拿来」是家庭机器人最典型的 open-vocabulary manipulation 指令，适合作为 VLA 产品 case 拆解。
- 表面一句话，底层是感知、 grounding、规划、抓取、导航、对话澄清的完整链路。
- PM 应能向非技术方解释：哪些步骤今天能做、哪些会失败、失败时用户体验如何设计。
- 本 case 可直接用于面试：5 分钟讲清 pipeline + 3 个关键指标 + 2 个已知局限。

## 核心概念

### 端到端 Pipeline

```
用户：「把杯子拿来」
    ↓
[1] 语音识别 + NLU → 意图=fetch, 目标=杯子
    ↓
[2] 视觉 grounding → 在场景中定位「杯子」实例（可能多个）
    ↓
[3] 歧义处理 → 「厨房还是客厅的杯子？」（若置信度低）
    ↓
[4] 导航（若杯子不在臂展内）→ 路径规划 + 避障
    ↓
[5] VLA / 抓取策略 → 观测图像 + 指令 → 末端轨迹或关节动作
    ↓
[6] 力控闭合 + 抬起 → 确认抓取成功（滑移检测）
    ↓
[7] 导航回用户 + 递送 → 语音确认「这是您要的杯子吗？」
```

### 各阶段关键指标

| 阶段 | 指标 | 典型挑战 |
|------|------|----------|
| Grounding | Referring 准确率 | 同类物体多个实例 |
| 抓取 | 单次成功率 | 透明杯、窄把手 |
| 导航 | 到达率、耗时 | 动态障碍、窄通道 |
| 端到端 | 任务完成率 | 误差逐级累积 |

### VLA 在此 case 中的角色

- **端到端 VLA**：图像 + 「bring me the cup」→ 直接输出动作 chunk
- **分层方案**：LLM 规划 + 专用 grasp model + 传统 motion planning
- 产品常选分层：可控性、可调试性、安全审核更容易

### 失败态产品设计

- 找不到杯子：主动询问或带用户到疑似位置
- 抓取失败：重试 2 次后请求人工辅助，不强行拖拽
- 递送途中碰撞：立即停止并语音告警
