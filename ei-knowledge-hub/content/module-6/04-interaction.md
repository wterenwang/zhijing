# 语音指令与行为反馈设计

家庭场景中，语音是自然的主交互通道，而灯光、声音、屏幕与机身动作则是建立信任的关键反馈。本章节设计核心指令集、模糊匹配策略，以及任务全生命周期的状态可感知性。

## PM视角要点

- 语音交互不是「接入智能音箱 API」这么简单。需定义 **领域指令集**（Domain-specific Commands）、槽位（Slots）、确认策略与纠错流程。
- 家庭环境嘈杂、多人说话、口音差异大。PM 要设计 **降级路径**：语音失败 → 触屏/APP → 物理按键。
- 行为反馈遵循 **可预测性原则**：用户应随时知道机器人在做什么、还要多久、为何暂停、如何介入。
- 异常场景体验决定口碑：抓取失败时不应沉默，应说明原因并给出下一步选项（重试/跳过/手动标记）。
- 输出物：指令-响应对照表 + 交互状态流转图 + 异常场景 UX 说明。

## 核心概念

| 概念 | 说明 |
|------|------|
| 意图（Intent） | 用户语音背后的任务类型，如「开始清扫」「捡起物品」「回充」 |
| 槽位填充（Slot Filling） | 从语句中提取参数，如位置「客厅」、物体「袜子」 |
| 确认机制 | 对歧义或高风险指令要求用户二次确认，如「要把这个杯子放到哪里？」 |
| 多模态反馈 | 语音播报 + LED 灯效 + APP 推送 + 机身动作的协同 |
| 可中断性 | 用户随时可说「停下」「取消」，机器人须在安全窗口内响应 |

### 核心语音指令集（示例）

| 意图 | 用户说法示例 | 系统响应 |
|------|--------------|----------|
| 开始清扫 | 「打扫一下客厅」 | 语音确认区域，灯效切换为清扫模式，APP 显示进度 |
| 物品归位 | 「把地上的玩具放进收纳箱」 | 若物体歧义则追问，执行中播报「正在捡起积木」 |
| 暂停/继续 | 「先停一下」「继续」 | 立即减速停止，灯效变黄；继续时恢复 |
| 回充 | 「回去充电」 | 播报预计路径，低电量时主动建议 |
| 状态查询 | 「扫完了吗」 | 播报完成度百分比与预计剩余时间 |

### 行为反馈状态设计

| 状态 | 灯效 | 语音 | 屏幕/APP |
|------|------|------|----------|
| 待机 | 常亮柔光 | 可选欢迎语 | 显示电量与上次任务 |
| 执行中 | 呼吸闪烁 | 关键节点播报 | 实时地图与进度 |
| 需要确认 | 黄色慢闪 | 追问语句 | 弹出选项按钮 |
| 失败 | 红色短闪 + 提示音 | 说明原因与建议 | 一键重试/反馈 |
| 充电中 | 绿色脉冲 | 低打扰 | 预计充满时间 |
