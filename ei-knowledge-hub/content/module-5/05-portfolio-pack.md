# 方案包装与模拟评审

项目一的收官阶段是把 PRD、竞品分析、商业模式压缩成可路演、可投递的作品集。面试官通常只有 10 至 15 分钟，你的 PPT 必须讲清「为什么做、做了什么、为什么这样取舍、下一步怎么验证」。

## PM视角要点

- PPT 页数建议控制在 10 至 12 页：封面、问题、用户、方案、功能亮点、开发者旅程、商业模式、里程碑、风险、总结。附录放详细表格。
- 每一页只传达一个核心信息。避免把 PRD 全文贴进幻灯片。
- 模拟评审时邀请朋友扮演「挑剔的技术 VP」：追问指标依据、竞品差异是否经得起验证、MVP 范围是否过大。
- 准备 3 个高频追问的标准答案：为什么不做 X？如何衡量成功？如果只有 3 个月你会砍什么？
- 视觉统一：配色、字体、图表风格与项目二保持一致，方便最终作品集整合。

## 核心概念

| 概念 | 说明 |
|------|------|
| 路演故事线 | Problem → Insight → Solution → Demo/原型 → Business → Ask/Roadmap |
| 电梯演讲（Elevator Pitch） | 60 秒内说清产品价值，用于封面页或开场 |
| 模拟评审（Mock Review） | 限时演示 + Q&A，提前暴露逻辑漏洞与表达短板 |
| 作品集（Portfolio） | 可独立阅读的 PDF/PPT，包含足够上下文让陌生人理解项目 |
| 决策追溯 | 在幻灯片中标注关键 trade-off 及理由，展示 PM 判断力 |

### 推荐 PPT 结构（项目一）

1. **封面**：项目名称、角色、日期
2. **背景与机会**：市场趋势、生态缺口（1 张图）
3. **目标用户**：2 个 Persona 卡片
4. **核心痛点**：Top 3，附调研来源
5. **解决方案概览**：SDK 工具链架构图
6. **开发者旅程优化**：Before / After 对比
7. **功能 MVP**：P0 功能与验收标准
8. **竞品差异化**：对比表精简版
9. **商业模式**：收入流 + 飞轮示意图
10. **路线图**：3 个阶段里程碑
11. **风险与下一步**：假设、待验证实验
12. **总结**：一句话价值主张

### 模拟评审检查清单

- [ ] 10 分钟内能讲完，不超时
- [ ] 每个数据点能说出来源（访谈、实测、公开报告）
- [ ] 技术术语能向非技术听众解释清楚
- [ ] 主动交代 1 至 2 个「没做」的功能及原因
- [ ] 结尾有明确的「若上线后第一周会看什么指标」
