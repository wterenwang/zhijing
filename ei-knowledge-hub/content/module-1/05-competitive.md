# 竞品差异化分析框架

> Day 5 | 建立可复用的竞品分析方法论

## 关联学习天数

**Day 5**

---

## PM 视角要点

竞品分析是产品经理的**核心基本功**，但在具身智能领域，传统互联网竞品框架不够用。今天要建立一套适配「软硬一体 + 长周期技术演进」的分析框架。

### 常见误区

| 误区 | 正确做法 |
|------|----------|
| 只看官网宣传 | 交叉验证：论文、GitHub、招聘 JD、用户评价 |
| 只比参数表 | 参数背后的工程权衡才是产品决策的关键 |
| 静态快照对比 | 加入时间维度：6 个月前的竞品和现在可能完全不同 |
| 罗列功能清单 | 聚焦「用户任务完成度」而非功能数量 |
| 忽视生态 | SDK、社区、合作伙伴是中长期壁垒 |

### 今日产出

一份 **具身智能竞品分析框架 v0.1**，包含 8 大维度、每个维度 3-5 个具体指标，可直接用于后续项目。

---

## 核心概念

### 竞品分析三步法

```
Step 1: 圈定竞品范围
    ↓  同形态 / 同场景 / 同客群
Step 2: 信息收集
    ↓  官方 + 第三方 + 一手体验
Step 3: 结构化输出
    ↓  矩阵对比 + 差异化洞察 + 策略建议
```

### 八大分析维度

#### 1. 产品定位

| 指标 | 说明 | 信息来源 |
|------|------|----------|
| 目标客群 | ToD / ToB / ToC / ToG | 官网、发布会 |
| 核心场景 | 首要解决的 1-2 个场景 | 案例、白皮书 |
| 价值主张 | 一句话卖点 | 官网 Slogan |
| 产品形态 | 人形/四足/臂/复合 | 产品页 |

#### 2. 硬件能力

| 指标 | 说明 | 信息来源 |
|------|------|----------|
| 自由度（DOF） | 关节数量与布局 | 产品规格 |
| 负载能力 | 末端/整机负载 | 产品规格 |
| 续航时间 | 典型工况续航 | 产品规格/评测 |
| 感知配置 | 相机/雷达/力觉数量与型号 | 拆解报告、规格 |
| 成本区间 | 售价或 BOM 估算 | 官网/行业报告 |

#### 3. 软件与 AI 能力

| 指标 | 说明 | 信息来源 |
|------|------|----------|
| 感知栈 | SLAM、目标检测、语义分割方案 | 论文、技术博客 |
| 决策架构 | 规则 / RL / VLA / 混合 | 论文、开源代码 |
| 任务泛化 | 能完成多少类任务，换场景是否需要重训 | Demo 视频、评测 |
| 端云协同 | 推理在端侧还是云端 | 架构文档 |
| Sim-to-Real | 仿真训练成熟度 | 论文、开发者文档 |

#### 4. 开发者生态

| 指标 | 说明 | 信息来源 |
|------|------|----------|
| SDK 完整度 | 语言支持、API 覆盖范围 | 开发者文档 |
| 仿真环境 | 是否提供高保真仿真器 | 文档、GitHub |
| 开源程度 | 核心代码/模型是否开源 | GitHub |
| 社区活跃度 | Star 数、Issue 响应、论坛 | GitHub、Discord |
| 第三方应用 | 生态应用数量与质量 | 应用商店、案例 |

#### 5. 商业化与交付

| 指标 | 说明 | 信息来源 |
|------|------|----------|
| 定价策略 | 硬件/软件/服务拆分 | 官网、销售 |
| 交付周期 | 下单到到手的时间 | 用户反馈 |
| 出货量 | 已交付数量级 | 新闻、财报 |
| 客户结构 | 头部客户 vs 长尾 | 案例、财报 |
| 售后体系 | 维保、培训、备件 | 服务条款 |

#### 6. 团队与资源

| 指标 | 说明 | 信息来源 |
|------|------|----------|
| 核心团队背景 | AI / 机器人 / 制造 | 官网、LinkedIn |
| 融资情况 | 轮次、金额、投资方 | 新闻、IT 桔子 |
| 专利布局 | 核心专利数量与方向 | 专利检索 |
| 制造能力 | 自产 vs 代工 | 新闻、供应链分析 |
| 招聘方向 | 当前急招岗位反映战略重心 | 招聘网站 |

#### 7. 数据与迭代

| 指标 | 说明 | 信息来源 |
|------|------|----------|
| 数据闭环 | 是否有真实场景数据采集机制 | 技术博客 |
| 迭代频率 | 产品/固件/模型更新节奏 | 更新日志 |
| OTA 能力 | 远程升级范围 | 文档 |
| 客户共创 | 是否与客户联合定义需求 | 案例 |

#### 8. 风险与短板

| 指标 | 说明 | 信息来源 |
|------|------|----------|
| 技术瓶颈 | 公开承认或外界质疑的短板 | 访谈、评测 |
| 供应链风险 | 关键零部件依赖 | 行业分析 |
| 合规风险 | 安全认证、数据隐私 | 认证信息 |
| 场景局限 | Demo 好看但量产的障碍 | 深度评测 |

### 差异化分析矩阵模板

将 Day 4 的四家公司填入以下模板：

| 维度 | 权重 | 我司 | 竞品 A | 竞品 B | 竞品 C |
|------|------|------|--------|--------|--------|
| 产品定位 | 15% | | | | |
| 硬件能力 | 20% | | | | |
| 软件与 AI | 25% | | | | |
| 开发者生态 | 15% | | | | |
| 商业化 | 10% | | | | |
| 团队资源 | 5% | | | | |
| 数据迭代 | 5% | | | | |
| 风险短板 | 5% | | | | |

> 权重可根据你所在公司的战略重心调整。例如做开发者平台的 PM 会把「生态」权重调高。

### 差异化洞察输出格式

每个竞品写三段：

1. **核心优势**（1-2 条，附证据）
2. **明显短板**（1-2 条，附证据）
3. **对我们的启示**（可借鉴 / 需规避 / 可差异化）

### 信息收集渠道清单

| 渠道 | 获取信息类型 | 可信度 |
|------|-------------|--------|
| 官网产品页 | 规格、价格、定位 | 高（但可能有宣传水分） |
| 技术论文/博客 | 真实技术路线 | 高 |
| GitHub | 开源代码、社区活跃度 | 高 |
| 招聘 JD | 战略方向、技术栈 | 中高 |
| 行业报告 | 市场数据、产业链 | 中 |
| 社交媒体/演示视频 | 能力上限展示 | 中（注意剪辑） |
| 用户评价/论坛 | 真实体验、交付问题 | 中高 |
| 供应链/拆解 | 真实 BOM、零部件 | 高 |
