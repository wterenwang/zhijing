# 作品集整合

两份独立项目产出需要打磨成 **一份** 让面试官在 15 分钟内看到完整产品能力的作品集。本章节覆盖排版统一、内容串联、导出定稿与外部审阅流程。

## PM视角要点

- 封面页应包含：姓名、求职意向（具身智能产品经理）、联系方式、作品集日期。避免花哨，专业感优先。
- 个人介绍页用 3 至 4  bullet 概括能力标签，例如「用户研究 / SDK 产品设计 / 家庭场景 VLA 方案 / 数据驱动迭代」，与两个项目一一对应。
- 项目排列建议：先放与你目标岗位更匹配的项目，或按叙事逻辑「平台 → 应用」排列。
- 每项目压缩为 6 至 8 页：问题、用户、方案、亮点功能、指标、商业模式（项目一）、技术方案（项目二）、成果与反思。
- 请至少 1 位非本专业朋友审阅：测试「不看口头解释能否看懂 70%」。

## 核心概念

| 概念 | 说明 |
|------|------|
| 视觉系统 | 统一的配色、字体、图标、图表样式，建议全作品集不超过 2 种主色 |
| 叙事弧线 | 从行业洞察到用户痛点到方案到验证，形成完整故事而非功能清单 |
| 成长曲线 | 用时间线或能力雷达图展示 90 天从认知到实战的进步 |
| 附录策略 | 详细 PRD 表格、完整竞品矩阵放附录，正文只保留决策级摘要 |
| PDF 导出规范 | 嵌入字体、压缩图片、文件大小控制在 15MB 以内便于邮件附件 |

### 推荐作品集目录结构

1. 封面
2. 关于我（能力概述 + 教育/经历）
3. 90 天学习路径一览（可选信息图）
4. **项目一：开发者生态 SDK 产品设计**
   - 背景与机会
   - 用户洞察
   - 方案与 MVP
   - 商业模式
   - 关键决策与反思
5. **项目二：家庭场景功能优化**
   - 场景与痛点
   - VLA 技术方案
   - 交互与指标
   - 关键决策与反思
6. 总结与联系方式
7. 附录（PRD 节选、用户画像、指标表）

### 整合检查清单

- [ ] 两个项目配色、字体、页眉页脚一致
- [ ] 所有图表有标题、来源与可读图例
- [ ] 无错别字，专业术语首次出现有简短解释
- [ ] 每项目有至少 1 个可量化的成果或目标指标
- [ ] 导出 PDF 在手机端可清晰阅读
