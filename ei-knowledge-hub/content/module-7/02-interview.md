# 模拟面试准备

面试官对具身智能 PM 的考察，集中在 **为什么做（Why）、怎么做（How）、取舍是什么（Trade-off）** 三个层次。本章节帮你为两个项目分别准备结构化回答，并完成至少一次 30 分钟完整模拟。

## PM视角要点

- **Why**：证明问题真实且值得做。引用用户访谈原话、市场数据、竞品缺口，避免「我觉得」式开场。
- **How**：证明方法论扎实。描述调研 → 定义 → 方案 → 验证的完整链路，突出你的个人贡献（「我主导了…」「我决策了…」）。
- **Trade-off**：证明判断力。每个项目准备 2 至 3 个「本可以做 A，但选了 B」的案例，说明约束与依据。
- 自我介绍准备两个版本：**1 分钟**（电梯版）和 **3 分钟**（含项目亮点），均须背熟到自然表达，非背诵感。
- 技术追问不必装专家。诚实划定认知边界，展示「足够与工程师对话」的理解深度即可。

## 核心概念

| 概念 | 说明 |
|------|------|
| Why-How-Trade-off 框架 | 面试项目题的三层回答结构 |
| 追问防御 | 预先准备「如果指标不达标怎么办」「竞品明天抄你怎么办」等尖锐问题 |
| 技术深度展示点 | 不需推导公式，但能解释 VLA、SDK、ROS 2、数据闭环对产品的含义 |
| 模拟面试 | 限时 30 分钟，含自我介绍、2 个项目、行业题、反向提问 |
| 答案库 | 高频题的标准化回答文档，持续根据真实面试反馈迭代 |

### 项目一高频题与回答要点

| 问题 | 回答框架 |
|------|----------|
| 为什么做开发者生态？ | 硬件同质化 → 生态是护城河；访谈发现 XX% 开发者卡在首次运行 |
| SDK MVP 为何这样划边界？ | 资源约束下优先 Time to First Run；可视化编辑器延后因为… |
| 商业模式是否可行？ | 冷启动免费 + 技能商店分成；对标 Unity/App Store 飞轮 |
| 最大 trade-off？ | 例：深度绑定自家硬件 vs 兼容 ROS 2，选了后者因为实验室用户… |

### 项目二高频题与回答要点

| 问题 | 回答框架 |
|------|----------|
| 为什么选清洁整理而非厨房？ | 安全/监管/成熟度三角；MVP 需 12 个月内可验证 |
| VLA 方案怎么评估？ | 成功率、延迟、物体集、成本四维度；引用 RT/OpenVLA 等调研 |
| 语音交互最大挑战？ | 嘈杂环境 + 歧义指令；设计了确认与降级路径 |
| 如何定义产品成功？ | 任务成功率 ≥ X%、CSAT ≥ Y、卡住率 ≤ Z%，附测试方案 |

### 行业通用题准备

- 你怎么看具身智能未来 3 年的商业化路径？
- 大模型对机器人产品形态有什么改变？
- 你如何做优先级排序（RICE / ICE / 价值-成本矩阵）？
- 描述一次你与工程师意见不合的经历。
