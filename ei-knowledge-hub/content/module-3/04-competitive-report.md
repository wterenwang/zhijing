# 竞品分析报告

## PM视角要点

- 竞品分析不是「抄功能清单」，而是回答：目标用户为何选 A 不选 B？我们的差异化是否可防御、可感知？
- 本模块 Day 18-20 的交付物是一份结构化报告，建议 8-12 页，含表格、截图、技术判断与产品建议。
- 分析维度应覆盖：定位、价格、硬件配置、软件能力、交互、开发者生态、数据策略、渠道与品牌。
- 需回溯第1周竞品框架，并结合第2-3周技术认知，避免「只看营销页、不懂实现难度」。

## 核心概念

### 报告结构模板

1. **Executive Summary**（1 页）
2. **市场与用户需求**（引用 Module 1 行业认知）
3. **竞品选取与矩阵**（3-5 个直接/间接竞品）
4. **功能对比表**（硬件、感知、智能、交互、价格）
5. **技术路线判断**（VLA vs 传统 pipeline、RL vs 示教等）
6. **SWOT 与机会窗口**
7. **产品建议与 roadmap implication**

### 对比维度清单

| 维度 | 考察点 |
|------|--------|
| 硬件 | DoF、传感器、续航、噪音 |
| 智能 | 开放词汇指令、泛化、多轮对话 |
| 交互 | 语音/APP/手势、失败态处理 |
| 生态 | SDK、开发者社区、第三方技能 |
| 商业 | 定价、订阅、ToB/ToC 策略 |

### 与 Module 1 的关联

请先阅读 [竞品差异化（Module 1）](/doc/module-1/05-competitive)，复用其中的分析框架与术语，在本报告中做「2.0 深化版」：加入你第2-3周的技术理解与家庭场景假设。

### 评分方法

- 为每个维度打 1-5 分，并注明信息来源（官网、评测、论文、实测）
- 区分「已实现」「demo 级」「路线图」三种成熟度，避免被宣传误导
